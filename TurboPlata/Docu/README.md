# 🚀 TurboPlata - Система управления производством

Монолитное приложение на Go для учёта выработки и управления производственными процессами.

## 🎯 Основные возможности

- 📦 Управление заказами и коробками
- 👥 Система аутентификации рабочих
- 🔍 Сканирование штрих-кодов (MQTT + HTTP)
- 📊 Журнал выработки
- 🔧 Техкарты и операции
- 💾 Автоматическое резервное копирование (каждые 15 мин)
- 🧹 Автоочистка старых записей (ежедневно в 3:00)

## 🏗️ Архитектура

- **Backend**: Go 1.21+ с SQLite (WAL режим)
- **MQTT**: Eclipse Paho для сканеров
- **Web UI**: Встроенные HTML страницы (vydacha, admin, master, otk)
- **Структура**: Монолит с горутинами

## 📦 Установка
    
### Требования
- Go 1.21 или выше
- Git

### Быстрый старт

```powershell
# Клонировать репозиторий
git clone <repo-url>
cd TurboPlata

# Скомпилировать
go build -o turboplata.exe .\GO\main.go .\GO\handle_employees.go

# Запустить
.\turboplata.exe

# С DEBUG-логами в отдельном окне (Windows)
$env:DEBUG_LOGGING="1"
.\turboplata.exe
```

## 🚀 Запуск

### Основной сервер

```powershell
# Из исходников
go run GO\main.go GO\handle_employees.go

# Скомпилированная версия
.\turboplata.exe
```

Сервер запустится на **http://localhost:8080**

### Debug Scanner (тестовая утилита)

```powershell
# Запуск
go run GO\debug_scanner.go

# Команды
scan USER_123456              # Авторизация рабочего
scan BOX_1_product_10_abc     # Создание коробки и регистрация первой операции на рабочего
scan ORDER_test_100_5000.50   # Создание заказа
scan DONE                     # Завершение текущей операции и начисление оплаты
                              # Универсальный код без номера
                              # Сервер автоматически привязывает к последней незакрытой операции сотрудника
end                           # Выход
```

## 🌐 API Endpoints

### Сканирование
- `POST /api/scan` - Обработка сканирования штрих-кода

### Рабочие и сотрудники
- `GET /api/workers` - Список рабочих
- `GET /api/employees` - Список сотрудников (без паролей)
- `POST /api/employees` - Добавить сотрудника
- `PUT /api/employees` - Обновить сотрудника
- `DELETE /api/employees?tabNo=N` - Удалить сотрудника
- `GET /api/auth?tab=TABLE_ID` - Проверка авторизации

### Заказы и коробки
- `GET /api/orders` - Активные заказы
- `POST /api/orders/sync` - Синхронизация заказов
- `GET /api/boxes` - Список коробок
- `POST /api/boxes` - Создать коробку

### Конфигурация
- `GET /api/config` - Получить конфигурацию (formulas.json)
- `POST /api/config/update` - Обновить конфигурацию

### Веб-интерфейсы
- `GET /` - Страница выдачи (vydacha)
- `GET /admin` - Админ-панель
- `GET /master` - Мастер участка
- `GET /otk` - ОТК (контроль качества)

## 🔧 Конфигурация

✅ Все глобальные данные защищены мьютексами (RWMutex)  
✅ Параметризованные SQL-запросы  
✅ Type assertions с проверкой  
✅ Запрет на удаление/изменение администраторов через API  

## 📝 Префиксы штрих-кодов

- `USER_<табельный_номер>` - Авторизация рабочего
- `BOX_<orderID>_<product>_<qty>_<extra>` - Создание коробки
- `ORDER_<name>_<planQty>_<price>_<extra>` - Создание заказа
- `DONE_<boxID>` - Завершение операции

## 🆘 Troubleshooting

### Проблема: Ошибка компиляции "main redeclared"
**Решение**: Убедитесь, что в `debug_scanner.go` есть `// +build ignore` в начале файла

### Проблема: MQTT не подключается
**Решение**: Проверьте, что MQTT брокер запущен на `localhost:1883`

### Проблема: HTML страницы пустые
**Решение**: Убедитесь, что файл `main.go.index.html` существует в директории проекта

### Проблема: Race condition warnings
**Решение**: Обновитесь до версии 0.17+ (все мьютексы добавлены)
